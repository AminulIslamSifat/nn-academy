## Detection vs Hunting

Detection is reactive (alert fires, you investigate). Hunting is proactive (you assume a breach exists and search for it). The best SOCs do both.

## The Hunting Cycle

1. **Hypothesis** — Based on threat intel, ATT&CK, or anomalies: "APT29 uses WMI persistence in our sector"
2. **Investigate** — Query logs, memory, and artifacts for evidence
3. **Analyze** — Determine if the hypothesis is confirmed or refuted
4. **Document** — Record findings, new IOCs, and detection opportunities
5. **Automate** — Convert successful hunts into detection rules

## Hunting Data Sources

| Source | What It Reveals |
|---|---|
| Process creation logs | Unusual parent-child relationships |
| DNS logs | C2 domain lookups |
| Authentication logs | Impossible travel, unusual accounts |
| File creation/modification | Malware drops, config changes |
| Network flows | Beaconing, data exfiltration |
| Memory dumps | Injected code, unpacked malware |

<Callout type="info" title="Hunt maturity model">Level 1: Alert-driven investigation. Level 2: Known IOC scanning. Level 3: Hypothesis-driven hunting. Level 4: Automated hunting with ML. Most organizations are at Level 1-2. Aim for Level 3.</Callout>

## Summary

Threat hunting proactively finds threats that evaded detection. Form hypotheses from threat intel and ATT&CK, query data sources systematically, and convert findings into automated detections. Hunting closes the gap between what your tools catch and what actually happened.
